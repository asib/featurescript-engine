# Fixture batch 001: sketch and extrude

106 cases that sketch lines, arcs, circles and rectangles and extrude them with std's `extrude` feature. They cover:
- blind, symmetric, two-direction, opposite-direction and negative extents;
- regions with holes and overlapping regions;
- new, add, remove and intersect operations;
- some language probes and two cases that should fail.

| file | what it is |
|---|---|
| `cases.fs` | One FeatureScript function per case. Runs unchanged in Onshape and on our engine. |
| `cases.json` | Each case's name, kind, description and grid slot. |
| `generator.fs` | Onshape only: a feature that builds every case, moves each case's solids to its grid slot and names them. |
| `onshape.step` | What Onshape built: the fixture our engine's models are compared against. |

All four files except `onshape.step` are generated by `node tools/fixtures/gen-batch-001.mjs` (seed 20261107).

## How the fixture was made

- **When and where:** 2026-11-07, Onshape build 1.223.92697, FeatureScript 3112, std 3112.0.
- **Document:** "featurescript-engine fixtures", private:
  <https://cad.onshape.com/documents/ab4356d36ac75fefa9174adb>. It has a Feature Studio holding `cases.fs` followed
  by `generator.fs`, and a Part Studio with one "Build fixture batch 001" feature.
- **Export:** the Part Studio was exported as STEP AP242 from the UI's export menu, with no preprocessing, as one
  file, in metres. No API calls were used.
- **Repeatable:** two exports of the same Part Studio gave identical `DATA` sections; only the timestamp differed.
- **Rebuild:** `node tools/browser/build-fixture-batch.mjs fixtures/batch-001 https://cad.onshape.com/documents/ab4356d36ac75fefa9174adb/w/e18244a2202126079f47b665`

## Reading the fixture

- **Names:** each case's solids are named `<case>.<n>`, for example `c017.1`. Onshape writes the name on the
  `MANIFOLD_SOLID_BREP` itself.
- **Position:** each case is translated by its `slotMeters` from `cases.json`. Subtract that to bring the case back
  to the origin, where our engine builds it.
- **Quick look:** `node tools/fixtures/step-summary.mjs fixtures/batch-001/onshape.step` lists every part with its
  face, edge and vertex counts and its vertex bounding box.

## Result

100 cases built one solid each. Six built nothing, so they have no part in the STEP file, and our engine must fail
on them too:

| case | kind | Onshape's error | why |
|---|---|---|---|
| c065, c069 | second-direction | `EXTRUDE_FAILED` | The first direction is flipped and the second end is also opposite, so both ends point the same way. |
| c097 | language-probe | "First operand of logical or conditional operator must be boolean, value is string" | `~` binds looser than `==`, so the condition was a string. |
| c102 | language-probe | "First operand of logical or conditional operator must be boolean, value is number" | The ternary is left-associative. |
| c105 | expected-failure | `EXTRUDE_FAILED` | Zero blind depth. |
| c106 | expected-failure | `EXTRUDE_NO_SELECTED_REGION` | Nothing selected to extrude. |

The language probes, read from the depth of each 10 mm square:

| case | expression | depth | meaning |
|---|---|---|---|
| c096 | `-2^2 + 5` | 9 mm | `-2` is a negative constant, so this is `(-2)^2 + 5`. |
| c097 | `("a" ~ 1 + 2 == "a3") ? 2 : 1` | fails | `~` binds looser than `==`. |
| c098 | `(true ?? false && false) ? 2 : 1` | 2 mm | `??` binds looser than `&&`. |
| c099 | `("x" is string == true) ? 2 : 1` | 2 mm | `is` binds tighter than `==`. |
| c100 | `2 * 3 % 4` | 2 mm | `*` and `%` share a level, left to right. |
| c101 | `2^3^2 / 64` | 8 mm | `^` is right-associative. |
| c102 | `true ? 1 : false ? 2 : 3` | fails | The ternary is left-associative. |
| c103 | `(1 < 2 == true) ? 2 : 1` | 2 mm | `<` binds tighter than `==`. |
| c104 | `-7 % 3 + 4` | 6 mm | `%` takes the sign of the divisor. |

One thing to note about the topology: a fully extruded circle comes out as 3 faces (1 cylindrical, 2 planar), with
2 circular edges, 2 vertices and no seam edge.
